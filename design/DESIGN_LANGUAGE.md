# 设计语言

方向：安静的浅色背景、清楚的字号层级、充分留白、真实产品画面、克制而有连续性的动效。品牌辨识来自开放圆环和产品内核；页面重心是用户能理解并使用两款工具。

## 色彩与语义

| Token | 色值 | 用途 |
| --- | --- | --- |
| ink | `#233C3D` | 主文字、深色单色标志 |
| muted | `#536766` | 次级文字 |
| paper | `#F6F8F5` | 官网背景 |
| line | `#D4DFD9` | 分隔线、轻边框 |
| suite | `#32665C` | LDSP 松绿、共同主张 |
| plugin | `#4B5EA8` | 插件靛蓝、安装动作 |
| plugin-soft | `#EEF0F9` | 插件浅色表面 |
| store | `#916625` | 士多矿金、产品识别 |
| store-soft | `#F6F0E3` | 士多浅色表面 |
| favicon darkColor | `#A7D9C8` | LDSP SVG favicon 在深色标签栏下的浅松绿 |

使用语义变量，不在组件中各自定义同名不同色的品牌色。普通白色表面可以配合 paper 使用。产品识别色与支付、订单、成功、警告、失败的业务语义色分别管理，状态同时有文字或图标，不单靠颜色判断。交易 UI 的已有主题和状态体系按功能渐进接入品牌，不整体涂成营销首页。

规则来自 [当前 identity](system/identity.json)，CSS 镜像见 [brand-tokens.css](system/brand-tokens.css)。实际编辑与同步流程见 [维护规则](GOVERNANCE.md)。

## 字体与层级

拉丁字母和数字使用 Manrope，中文使用 Noto Sans SC，系统回退为 PingFang SC／Microsoft YaHei／sans-serif。技术标注使用系统等宽字体。本地 WOFF2 子集和 OFL 文件一并保存，字体名称与加载细节以 [官网 CSS](../website/src/brand.css) 为准。

| 元素 | 已发布官网基线 |
| --- | --- |
| 首屏标题 | `clamp(54px, 6.7vw, 86px)`，字重 650，行高 1.12；≤800px 为 62px，≤480px 为 53px |
| 二级标题 | `clamp(32px, 4.4vw, 56px)`，行高 1.3，适当负字距 |
| 首屏说明 | 桌面 17px／行高 1.8；≤800px 为 15px，≤480px 为 13px |
| 品牌眉题 | 桌面 13px，字重 650；小屏缩小并保持短文案 |
| 主按钮 | 桌面 13px，字重 650，最小高度 46px；小屏最小高度 44px |

以上是当前营销页面的实现记录，不把其小尺寸图注套用到交易、支付、表单、帮助正文等关键内容。标题有明确主次，长中文标题避免落单尾字；数据展示可用等宽数字。品牌字标和分享图文字转路径，正文保留可选择、可访问的真实文本。

## 布局与组件

桌面官网内容宽度上限 1180px，左右留白各 40px；普通区段上下留白 110px。中屏缩小为 80px、小屏约 65px，并以实际内容校验。按钮圆角 8px，产品窗口通常 12px，插件展示容器 14px；不为每个组件增加新的圆角语言。

双产品首屏以士多桌面窗口和插件原生面板形成层次；后续分开说明产品价值和使用入口。先展示主张，再给证据，再引导行动。每个产品以三项关键能力为主要说明，避免堆叠后台技术名词。

| 组件 | 规则 |
| --- | --- |
| 页头 | 品牌、四个主要导航、GitHub Star；小屏折叠菜单，仍能找到 Star 与产品入口 |
| 主行动 | 「安装 LDStatusPro」「打开 LD 士多」，以动作命名；每个区段保持主次明确 |
| 箭头 | 默认不加装饰箭头；首屏仅保留向下探索提示。展开、下载、主题切换等功能图标可保留 |
| 分段选择 | 清楚标明浅／深主题、升级要求／阅读趋势、物品广场／小店集市；选中状态有视觉与语义反馈 |
| FAQ | 原生 details／summary，Plus 提示展开；键盘、焦点与无动画状态均可使用 |
| 署名 | Jacky 简短身份与 GitHub 回链；产品官网不增加完整个人作品展示区 |
| 截图窗口 | 工具栏轻量，图片比例真实，功能信息不被装饰遮挡 |

组件反馈和滚动编排按 [动效规范](MOTION_AND_MEDIA.md)。同一动作在入口、界面和帮助文案中使用同一称呼。版本来自实际脚本元数据，不在不同页面分别写死。

## 桌面、平板与手机适配

断点按可用宽度决定，不依据设备名称猜测布局。平板横屏可能使用双列，竖屏可能使用单列。

| 宽度 | 当前规则与后续验收重点 |
| --- | --- |
| ≥1101px | 桌面完整导航与双列产品介绍；宽度受 1180px 内容区控制 |
| 801–1100px | 紧凑桌面／平板横屏；缩小间距，保留双列，避免按钮和标题挤压 |
| 481–800px | 平板竖屏／大手机；左右各 24px，页头 66px，单列产品与开始使用区，折叠菜单 |
| 361–480px | 手机；左右各 18px，缩小产品展示与非关键图注，主要控件至少 44px |
| ≤360px | 紧凑手机；进一步缩小面板组合并保证无遮挡、无横向溢出 |

官网上的士多展示始终使用真实桌面比例的高清素材，不用平板截图冒充桌面产品。响应式页面可以缩小整张截图，但不能压扁、拉长图片或截掉关键界面后仍称完整桌面截图。

后续视觉验收覆盖 320、390、768、1024、1280、1440px，并检查平板横竖方向。这里是验收范围，不声称每次文档更新都完成了全部设备测试。触屏不依赖 hover；菜单、主题切换、FAQ 均须可点按和键盘操作。

## 可访问性与文字

新界面验收检查正文／按钮文字对比度 4.5:1，大字 3:1；控件边界按实际辨识用途检查，轻分隔线不能替代必要控件边界。可操作元素有可见键盘焦点，页面保留跳过导航入口，锚点避开固定页头。图标旁已有同义文字时标为装饰；独立图标按钮有可访问名称。

页面说用户能完成什么，而不是如何构建。用「安装」「打开」「查看」「提交反馈」等具体动作；说明支持站点、脚本管理器、LDC 和交付规则。错误与空状态给出下一步，不用模糊情绪词。原生产品截图、演示数据、历史统计都有明确标注。
