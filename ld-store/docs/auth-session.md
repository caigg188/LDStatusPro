# 商城登录态与会话边界

JWT 是唯一持久化的登录凭据。`src/utils/auth.js` 维护共用会话快照，Pinia 用户状态、普通请求、下载和 SSE 均使用它。身份为 `(site, 数字用户 ID)`；用户名、头像和信任等级取自 JWT，不从独立的 `user` 缓存覆盖身份。旧版本缓存仍可恢复有效 JWT，旧 `user` 缓存被忽略。

## 恢复、切换与到期

- 登录时存储寿命跟随 JWT 的 `exp`，恢复会话不会延长授权。
- `storage` 事件同步跨标签页登录、退出及清空；窗口聚焦和页面恢复可见时重新校准。
- 本地提前 30 秒处理到期。定时器支持超过浏览器单次定时上限的有效期，后台休眠后会重新校准。
- 登录、退出、凭据变化都会更新会话版本，立即清空用户相关缓存、取消确认弹窗并重建通知连接。相同账号重新授权也会隔离旧请求。

## 请求与 OAuth 回调

带登录态的请求在开始时捕获会话，响应、响应体解析及异常处理后再次校验。旧会话的成功数据或错误都返回 `SESSION_CHANGED`，不能清掉新凭据。读取存储时发现界面尚未同步的账号变化，当前操作直接取消，避免把旧界面的操作发送给新账号。`auth: 'none'` 明确用于公共接口。

OAuth 候选凭据先检查格式、到期时间及身份一致性，再由 API2 `/api/shop/auth/verify` 校验签名和身份；确认成功并保存凭据后才提示成功、跳转。临时网络或服务错误可以重试校验。候选凭据及时从 hash/query 和浏览器历史中移除，离开回调页会取消校验。回调页自身负责会话竞争校验，不因全局缓存重建丢失候选凭据。浏览器本地检查不能替代服务端签名验证。

## 相邻业务边界

CDK 导出使用公共 API 客户端，下载中的账号变化会丢弃结果。下单恢复保持原有幂等令牌、超时查单和显式重试机制；会话切换或页面卸载后不继续恢复或提交。发布和编辑在图片验证、规则确认等等待点之后检查原会话；草稿始终保存、清理在打开编辑器时的账号下。

通知广播频道与连接持有者租约按论坛和用户 ID 隔离。取消的 SSE 不再派发缓冲中的旧消息；旧连接握手和结束回调不能清理新连接的超时、心跳定时器。

## 验证与发布

执行 `npm run check` 和 `npm run test:e2e`。新增测试覆盖跨标签页切换/退出、旧请求与旧 401、过期/损坏凭据、UTF-8 资料、存储失败、OAuth 校验及重试、闲置到期、CDK 下载、弹窗、下单恢复、草稿归属、通知频道和 SSE 取消。已有订单、优惠券、价格重确认、支付窗口及卖家发货规则回归继续执行。

单元测试禁用真实网络；浏览器使用独立 Vite 配置、显式 API/OAuth/支付模拟并阻止外部请求。生产只检查发布资源及健康响应。前端发布仍采用本机提交、推送和 `npm run deploy`，部署前记录上一提交和 Pages 部署地址作为回退依据。
