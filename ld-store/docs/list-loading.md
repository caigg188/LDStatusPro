# 列表加载合同

## 目标与范围

2026-10-18：修复小店、商品、订单、搜索、收藏的续载中断、漏页和旧响应污染；补齐商家商品与我的求购后续入口。
首页商品、小店、分类、搜索和商家商品采用自动续载，并始终保留按钮。订单、收藏与管理列表保留手动续载或分页。

## 实现边界

- `LoadMore.vue` 只拥有滚动监听、激活生命周期和加载／错误／完成反馈。业务页面及其 controller/store 拥有查询、数据、分页与请求取消。
- 页码和游标只在当前请求成功后提交。旧请求既不能追加内容，也不能回滚新查询的状态。失败保留已加载内容及分页位置；重试同一页。
- 自动续载遇错暂停，用户重试后恢复；不支持 IntersectionObserver 时按钮仍可用。每页完成后重新观察当前节点，支持节点重建与不足一屏的列表。
- Search、MyFavorites 与 Home、Category 一样使用现有、按登录会话分区的 KeepAlive；停用时取消请求／计时器，返回时保留内容、筛选和滚动位置；详情中修改收藏／屏蔽后，仅在偏好数据变化时重读至原深度。
- 收藏删除会改变 OFFSET。成功删除后只重新读取最后一个已加载页并补齐尾部，避免下一页跳过被移动的条目。
- 商家主页沿用身份与可见性过滤，接口返回每页至多 24 件及 `pagination.hasMore`。我的求购使用每页 20 条的普通分页。
- 求购广场每轮生成 `sortSeed`，翻页沿用该值；“换一批”生成新 seed 并回到第一页。无需服务端快照存储或新依赖。

## 验收

已复现缺陷均有回归场景；商家接口仅在对应页面加载，避免无状态的商家查询扩大商品 store 与首页入口包。

隔离单测覆盖失败后原页重试、查询切换、停用／恢复、收藏删除与并发搜索；浏览器覆盖桌面和移动端的筛选续载、失败恢复、搜索返回，以及商家第 25 件与我的求购后续页。
API2 用隔离 PostgreSQL 验证商家可见性分页与求购同 seed 无重叠。测试不加载生产配置且阻断外部副作用；生产发布只做非测试检查与只读验收。
